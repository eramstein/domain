When creating or updating a system:

Phase 1 - Review

1. Read architecture.md
2. Read current-focus.md
3. Read the target system document
4. Read 2-3 similar system documents

Review the document for:

- consistency with architecture
- consistency with existing systems
- missing edge cases
- ambiguous requirements
- unnecessary implementation details

Do not implement yet.

Produce:

- suggested improvements
- questions requiring clarification
- updated system document

Wait for approval.

Phase 2 - Planning

After approval:

1. Identify affected code areas
2. Produce implementation plan
3. List files to create or modify

Wait for approval.

Phase 3 - Implementation

After approval:

1. Implement changes
2. Add tests
3. Verify acceptance criteria
4. Update affected documentation

Phase 4 - Documentation Sync

If implementation required design changes:

- update the system document
- update related system documents
- create decision record if architecture changed
